# STARFLIGHT: ODYSSEY — PROJECT DOCUMENTATION & AGENT HANDOVER GUIDE

This document serves as a complete technical guide, architectural reference, and state summary for **StarFlight: Odyssey**. Any AI assistant or developer taking over this project should read this guide to understand the codebase structure, game systems, implemented features, key bindings, and recent bug fixes.

---

## 1. Project Overview & Technology Stack

* **Technology**: Pure HTML5 Canvas, Vanilla CSS3, and Modular ES6 JavaScript.
* **Dependencies**: None (Zero external libraries or npm build steps required). Runs natively in any modern web browser by opening `index.html`.
* **Visual Style**: Retro Sci-Fi CRT Terminal aesthetic with scanline overlays, neon green phosphor styling (`hsl(140, 100%, 50%)`), custom Google Fonts (*Share Tech Mono* & *Orbitron*), and dynamic screen-scaling transforms.
* **Audio**: Real-time Web Audio API synthesizer (`js/audio.js`) producing engine pitch bends, radar sweeps, laser blaster bursts, alarm sirens, and UI confirmation beeps without external sound files.

## 3. Core Game Loop & State Machine

The master controller is `window.game` (`GameManager` in `js/game.js`).

### Game View States (`game.viewState`)
* `"intro"`: Main Title Screen with Start Game, Import Save, Export Save, Reset Game options.
* `"spaceport"`: Starbase Prime terminal command (Ship Dept, Personnel Office, Commodity Market, HQ Logs).
* `"navigation"`: Space navigation canvas (Hyperspace interstellar travel & Solar System orbital navigation).
* `"landing"`: Planetary surface exploration grid (Terrain Vehicle TV driving, sample gathering, hazard avoidance).
* `"encounter"`: Alien communication and tactical combat view.
* `"barter"`: Commodity trading dialogue overlay during alien encounters.

### Space Flight Modes (`game.spaceState`)
* `"hyper"`: Hyperspace map navigation. Starbase Prime located at `(100.0, 100.0)`. Coordinates are in Light Years (LY). 1 LY = 14px on canvas.
* `"system"`: In-system orbital navigation centered on star at canvas coordinates `(300, 190)`. Orbiting planets follow physics rotation angles.

## 4. Subsystem Details & Key Features Implemented

### A. Viewport Aspect-Ratio Scaling & Fullscreen
* Dynamically scales `#game-container` in `css/style.css` to fill window space while maintaining a crisp retro CRT aspect ratio.
* Includes a native HTML5 Fullscreen API toggle button (`FULLSCREEN: ON/OFF`) in the upper-right header console.

### B. Hardened Main Animation Loop (`js/game.js`)
* `requestAnimationFrame((t) => this.tick(t))` is scheduled **FIRST** at the top of `tick(timestamp)`.
* All rendering and state updates are wrapped inside a `try ... catch` block.
* If a transient rendering or calculation exception occurs, it is logged safely to the console without interrupting the 60 FPS starfield animation loop.

### C. Save File Export & Import (`js/game.js`)
* **Auto-Save**: Saves game state to `localStorage` on major state transitions (docking, landing, market transactions).
* **Export Save**: Download save state as a readable `.json` file (`starflight_save_YYYY-MM-DD.json`).
* **Import Save**: File picker upload on the title screen or spaceport menu to restore game state from a saved `.json` file.

### D. Commodity Market & Realistic Cargo Mass System (`js/data.js` & `js/ui.js`)
* Each commodity has distinct, realistic mass attributes (0.1 T to 4.0 T):
  * `Iron`: 2.0 T | `Gold`: 3.0 T | `Platinum`: 3.5 T | `Endurium`: 1.5 T | `Precursor Alloy`: 4.0 T | `Flora`: 0.5 T | `Fauna`: 1.0 T | `Art`: 0.8 T | `Contraband`: 0.5 T | `Fuel`: 0.1 T.
* **Ship Manifest (`CARGO LOG [I]`)**: Inspect ship cargo hold mass, volume, item list, with `JETTISON 1` and `JETTISON ALL` action buttons.
* **Commodity Exchange (`js/spaceport.js`)**: Sell gathered minerals and biological samples at Starbase Prime for M.U. credits.

### F. Full-Screen Interactive Nav-Computer Star Map & Star Discovery (`#starmap-modal` & `js/navigation.js`)
* **Open via `STAR MAP [M]` Button or `[M]` Key**: Displays a full-screen vector Starmap Matrix filling 94% of the CRT console viewport.
* **Automatic Star System Proximity Discovery**: Flying within 18.0 Light Years of any star system in Hyperspace automatically discovers the star system, logs it to `ship.discoveredSystems`, plays a discovery chime, and prints a terminal log (`NAV DISCOVERY: STAR SYSTEM SIRIUS SECTOR (COORD: X 120, Y 85) LOGGED TO MAP.`).
* **Radar Scan Discovery (`RADAR SCAN [S]`)**: Emitting a Radar Scan (`[S]`) sweeps space up to 35.0 Light Years away, discovering and logging all star systems within sensor range.
* **Discovered System Mapping**: All discovered star systems are permanently mapped on the Nav-Computer Star Map with glowing star spectral colors, system names, and exact coordinates. Uncovers Fog of War sectors around discovered systems.
* **Flashing Position Marker**: Displays a pulsing cyan **`▶ YOU ARE HERE`** targeting reticle centered at `(shipX, shipY)`.

### G. Alien Ships in Space Navigation, Radar Scanning & Encounter Markers (`js/navigation.js` & `js/encounter.js`)
* **Visible Alien Spacecraft in Space Navigation**: Alien starships (Spemin Scouts, Veloxi Battlecruisers, Uhlek Interceptors) fly along real-time vectors across the main space flight canvas with glowing thrusters, radar aura rings, and coordinate labels.
* **Radar Scan Alien Detection (`RADAR SCAN [S]`)**: Running a Radar Scan (`[S]`) detects all active alien vessels in space up to 40.0 Light Years away, logging their name, exact `(X, Y)` coordinates, distance, and bearing vector to the terminal.
* **Active Alien Vessels on Star Map**: The full-screen Nav-Computer Star Map (`[M]`) renders active alien starships currently in flight as color-coded triangle markers (`▲ SPEMIN SCOUT (78.0, 72.0)`).
* **Past Alien Encounter History Markers**: Every alien meeting or battle is recorded in `ship.encounterHistory` and displayed on the Star Map with yellow battle icons (`⚔ [ENCOUNTER: SPEMIN BLOBS]`).
* **Proximity Comms Control (`COMMS [C]`)**: When an alien ship flies near your vessel (< 6.5 LY), a `COMMS [C]: <ALIEN SHIP>` button appears on your dashboard. Comms are no longer forced automatically for neutral/friendly ships—players can press **`[C]`** to open comms or simply fly past.
* **Encounter Cooldown Immunity (25 Seconds)**: Added `game.encounterCooldown = 25.0` upon concluding comms, fleeing, or winning combat. Prevents alien encounters from restarting frame-after-frame.

### H. Crew Medical & Healing System (`js/game.js` & `js/navigation.js`)
* **Starbase Infirmary Docking Healing**: Docking at Starbase Prime (`[L]`) automatically treats and fully restores all crew members to 100% full health (`MEDICAL INFIRMARY: ALL CREW MEMBERS TREATED AND RESTORED TO 100% HEALTH`).
* **Passive Doctor Healing in Flight**: Having a Doctor officer assigned to your crew (`ship.crew.doctor`) passively heals all injured crew members during flight (healing rate scales with Doctor's medical skill).
* **Natural Recovery**: Even without a Doctor, injured crew members slowly recover health over time while flying in space.

68. **Flight Jerk: Drag Was Applied Per-Frame, Not Per-Second (v1.9.23)**:
    * **Root Cause Solved**: in both `updateHyper()` and `updateSystem()`, thrust was correctly scaled by elapsed time (`* thrust * dt`) but drag was a flat per-**frame** multiply - `this.shipVx *= friction`. Velocity therefore depended on how many frames elapsed rather than how much time did, so **every wobble in frame duration directly changed the ship's speed**. A long frame applied a longer burn but only one step of drag, producing a forward lurch; a burst of quick frames bled speed off. That is the intermittent jerk felt while flying, and it happens even at a healthy average frame rate because only the *variance* matters.
    * **Frame-Rate Dependence**: the same bug made cruise speed scale with frame time. Measured terminal velocity after a 6-second burn: **9.40 at 30 FPS, 4.70 at 60 FPS, 1.96 at 144 FPS - a 380% spread**. A 144 Hz monitor flew the ship at 42% of the intended speed; 30 FPS flew it at double.
    * **Fix**: `const drag = Math.pow(friction, dt * 60)`. This is mathematically identical at 60 FPS (verified byte-for-byte: 4.70 before and after) while removing the dependence elsewhere. Post-fix spread across 30/60/144 FPS is **5%**, and a 50 ms hitch every 20 frames now deviates **0.4%** from steady flight.
    * **Render-Loop Allocation Trimmed**: `drawHyper()` rebuilt label strings with `.toUpperCase()` for every visible object every frame and the HUD ran three `document.getElementById` lookups per frame. Added `Navigation.labelFor()` (computes once, caches on the object) and `Navigation.setHudText()` (caches the nodes and writes only when the text actually changes). This does not fix the jerk - it reduces needless GC pressure in the hot loop.
    * **What Profiling Ruled Out**: a 45-second instrumented capture showed p50 frame time at a perfect **16.7 ms** with game logic costing **under 1 ms even inside 40-74 ms spike frames** - so the spikes were never JS execution. Ablation (disabling wormholes, patrols, nebulae, star systems, salvage sites and black holes in turn) moved nothing, ruling out any single renderer. Forcing `shadowBlur` off cut spikes from 13 to 7 over 10 seconds, a modest contributor worth remembering but not the cause. Note that the residual spike *rate* varied wildly between identical headless runs, so that measurement is not a reliable proxy for real hardware; the drag bug, by contrast, is deterministic and reproducible.

69. **Progression Pacing & Remaining Frame Hitches (v1.9.24)**:
    * **Two More Frame-Rate Dependencies**: `draw()` called `resizeCanvas()` **every frame**, and reading `parentElement.clientWidth` forces a synchronous layout. Because the HUD writes text to the DOM each frame, the layout was always dirty, so **every single frame paid a forced reflow**. Resizing is now event-driven (window resize, fullscreen change, view switch). Measured: forced layout reads fell from ~896 to **1** over 15 seconds, p99 frame time from ~25-30 ms to **19 ms**, worst frame from 35-74 ms to **29.7 ms**, and frames over 33 ms from 9 to **zero**. Separately, the starfield twinkle stepped a flat `+= 0.05` per frame, so the whole background strobed 2.4x faster on a 144 Hz display; it is now time-based.
    * **Pacing Rebalance**: with flight made frame-rate independent in v1.9.23, the true cruise speed turned out to be far too high - the entire 500 LY quadrant crossed in 1.7 minutes, or 37 seconds with a Class 5 drive. Combined with a galaxy holding roughly 40x more mineral wealth than it costs to buy everything, progression finished almost immediately. Three levers were pulled together:
      * **Hyperspace thrust to ~25%** (`(2.5 + engineLevel * 2.0)`), keeping the same 2.8x span between Class 1 and Class 5. In-system thrust to 50%, since system space is small.
      * **Deposit density roughly halved** - minerals `0.15 -> 0.07`, bio `0.12 -> 0.06` per tile - so stripping a world means real driving.
      * **Mined commodity sell values halved** across iron, gold, platinum, raw Endurium, precursor alloy, flora and fauna. Buy values were left alone, which also makes Endurium fuel meaningfully more expensive in relative terms.
    * **Resulting Pacing**: crossing the galaxy takes **7.1 minutes** at Class 1, 3.8 at Class 3, 2.6 at Class 5. A median planet now holds **$18,899** stripped bare (was $78,540), against $152,650 to buy everything - so full progression needs roughly **8 planets stripped instead of 2**, and the galaxy is about 10x oversupplied rather than 40x. An L1 rover bed-load nets **$908**; Class 2 engines cost 2 bed-loads, Class 3 costs 5, and the Class 5 Fold Engine costs **25**.

73. **PHASE 4 - Resource Variety & World Character (v1.10.3)**:
    * **The Problem**: every planet rolled from the same five minerals with hardcoded thresholds, so an ice moon and a volcanic hell yielded identical ore. Worlds had no character and there was nothing rare worth travelling for.
    * **13 New Commodities (`js/content/resources.js`)**: sulfur, silicate, titanium, obsidian, cryogenic crystal, iridium, void glass, singularity dust, spore mat, crystal lichen, thermophile colony, abyssal bloom and precursor seed vault - 23 in total. Every commodity, old and new, now carries a declared `tier` (common / uncommon / rare / exotic) so rarity is stated rather than implied by price.
    * **World Profiles**: a profile matches on the planet fields that **already existed** (`temp`, `atmosphere`, `gravity`, `bio`, `hasRuins`), so no planet data had to be re-authored. Seven profiles - airless, toxic, high-gravity giant, volcanic, ice, living, standard terrestrial - each declaring what that kind of world can bear. **Anything absent from the profile simply is not there.** Cryogenic crystal exists only on ice worlds; singularity dust only on high-gravity giants; airless bodies grow nothing at all, and the bio table is genuinely empty rather than merely unlikely.
    * **Ruins Are An Overlay, Not A World Type**: the first implementation made `hasRuins` a profile, which meant a Precursor ice moon **stopped being an ice moon** and three other profiles never fired at all. Ruins now merge on top of whichever physical profile matched, so a ruin ice world still yields cryogenic crystal and additionally yields precursor alloy and void glass.     * **Ordering Matters**: profiles are tested in order and the first match wins, so the narrow physical conditions (no atmosphere, corrosive atmosphere, crushing gravity) are tested **before** temperature - otherwise a 2.1g methane moon is classified by its temperature and the gas-giant profile never fires. Funding every upgrade takes about **14 stripped planets**, against 8 before this change and 2 before the v1.9.24 pacing pass.

The tooltip's `known` flag was aligned to the tier for the same reason.
    * **Captain's Log Drill-Down**: star systems expand to show their worlds across three tiers of knowledge - orbital elements only, then scan readings, then what the rover actually brought back (minerals and biologicals by name, artifacts, empty chambers, wrecks). Backed by a new `ship.planetSurveys` dossier written as you scan, land and collect.
    * **Salvageable Kills**: a destroyed ship now leaves a drifting hull worth stripping - credits plus ore scaled to what the ship was (Spemin iron through Uhlek iridium). Previously winning a fight produced nothing but a bounty. These wrecks are deliberately transient and unsaved: a battlefield is worth returning to only while it is still warm.
    * **Asteroids And The Tractor Scoop**: asteroid fields now span the Phase 4 tiers including iridium, cryogenic crystal and void glass. The scoop also **respected no cargo limit at all** and would load ore into a full hold; it now refuses and says so.
    * **Multi-Region Star Map**: the map gains a chart selector for regions already visited. Reviewing a region the ship has left reads that region's own exploration record, hides the vessel marker and labels itself `ARCHIVED CHART`. The view override is cleared on close - left set, it leaked out of the map and made *gameplay* contact lookups consult a region the ship was not in.

77. **The Corps Beacon & The Reveal That Was Never Wired (v1.11.4)**:
    * **`MAP DISCOVERIES` Was A Promise The Code Never Kept**: the probe-salvage button has always read `DOWNLOAD TELEMETRY LOGS (REWARD: +500 M.U. & MAP DISCOVERIES)`, but `handleDistressOption("salvage_probe")` only ever added credits. **No probe in the game has ever revealed a single sector.** Salvaging one now folds its survey run into the chart via `UI.mergeProbeTelemetry()`, and says how many sectors were new - or says plainly that the probe covered ground you had already charted, so a zero result reads as an answer rather than a failure.
    * **`sig_reach_1` Had A Story And No Ending**: the Shattered Reach beacon describes a Corps survey whose registry predates the founding of Starbase Prime by four centuries, then routed to the generic `probe_salvage` event and paid out 500 M.U. with a log line about an automated telemetry probe. The mystery was stated and dropped. It now carries its own `corps_beacon` event: decoding the final transmission of survey vessel *Endurance*, Corps registry 004, recovers the chart it died carrying (a 130 LY sweep - out there that is the only chart there is), a 900 M.U. records bounty, and a Captain's Log clue establishing that the Corps crossed the singularity first, could not get back, and **did not find the Reach empty**.
    * **Beacons Can Carry Clues As Data**: rather than hardcoding the above, any distress signal may declare a `grantsClue` record, plus optional `bounty` and `chartRadius`. Resolving it records the clue (deduped, sourced as `beacon`) and fires `QuestEngine.notify("beacon", ...)`. A future beacon is a content record in `js/content/regions.js`, not an edit to `js/ui.js`.
    * **`salvage_site` Objectives Resolved Late (`js/game.js`)**: `markSalvaged()` mutated `ship.salvagedIds` without telling the quest engine, and the `salvage_site` handler is state-driven - so an objective to salvage a specific site sat unresolved until some unrelated event happened to trigger an evaluation. It now fires `notify("salvage", {siteId})` directly. Latent rather than visible, because no shipped quest uses `salvage_site` yet; it would have bitten the first one that did.
    * Sweep extended to **198 checks** covering the charted reveal, the distinct beacon event, clue dedupe across two answers, save round-trip, the ignore path granting nothing, and the salvage notification.

78. **World Structure Round (v1.12.0 - v1.12.3)**:
    * **Wormholes Were The Same Eight Coordinates In Every Game (`js/wormholes.js`, NEW)**: four mirrored pairs at fixed points, so one playthrough taught you the whole network forever. The network is now rolled per save and stored whole under `ship.wormholeNet` - stored rather than seeded, because a captain's chart must not rearrange itself if the generator is later tuned. Placement enforces minimum separation, a minimum hop worth flying, and clearance around Starbase Prime. Some throats are **one-way**: a single mouth that ejects you with no return, and you cannot tell which is which until you scan it.
    * **Only One Black Hole Led Anywhere**: `bh_1` opened onto the Reach; the other two just flung you across the same quadrant. Gates are now declared in data (`leadsTo` / `oneWay` / `exitAt`) and resolved in one place by `Navigation.resolveGateway()`. Two new regions were authored as pure data - **The Marrow** and **The Lattice** - and the deep space forms a circuit: the Abyssal Gate is one-way into the Marrow, nothing in the Marrow opens back onto charted space, and its only exit falls deeper into the Lattice, which has the door home. Going in is a commitment.
    * **Making Every Well A Door Killed The Displacement Mechanic**: the sweep caught that no plain hazard singularity remained anywhere in the game. Three were added back that displace and nothing more, so reading the chart before flying still matters.
    * **Alien Ports Were Libraries With Docking Clamps**: docking opened an archive and nothing else, and ports were rendered core-only, so the deep regions had nowhere at all to refuel. Ports now sell reactor mass at their own price and buy cargo at their own rates - a premium for what that race wants, a discount for everything else. Every region past the fold has exactly one, priced by distance from anyone's supply line (48 in the Reach, 39 from the Spemin stuck in the Marrow, 62 at the Veloxi deep station; Starbase Prime charges 15).
    * **Structural Modules Need A Drydock**: splicing an amplifier into the sensor loom is field work. Re-cutting an engine mount, bonding hull plate, or opening the hold to fold it is not. Those three stow into `ship.pendingModules` and are fitted at a new gravity drydock at Starbase Prime for 15% of module value. Salvage-led growth still works - it just has to survive the trip home.
    * **Nebulae Did Nothing At All**: every cloud shipped with a description promising an effect and none were implemented, and they were invisible from the cockpit - drawn on the star map only, while the viewport showed an unrelated screen-locked haze that never moved. All eleven now carry the effect they always claimed: ionised fields triple shield recharge, interference cuts scan range 60%, Endurium clouds trickle fuel, gamma rifts drain shields and burn unshielded plating, compression fields stress the hull regardless of shields, and a dampening field genuinely hides the ship from alien acquisition. Drawn world-locked with a visible boundary.
    * **Systems Held Nothing But Planets**: every star looked identical once you were inside it. Roughly a third of systems now carry orbital sites - stations, drifting hulks, debris belts - generated deterministically from the system name, so nothing needed authoring by hand and the new regions got them for free. In-system scan lists them, because a scan reporting only planets in a system holding a wreck is a scan that lied.
    * **Ruins As Working Precursor Gates (`js/planet.js`)**: about a third of ruin worlds hold a frame that still draws power. Worlds the lander refuses outright - 3G+, 450°C+, -180°C- - are now genuinely unlandable, and a gate is the only way onto their surface. Stepping through records the exact return tile in `ship.portalReturn`, and the arrival tile **is** the return frame: there is no lander on a gate world, so that frame is the only way off. Verified that no artifact world was made unreachable by the landing block.
    * **Gate Return Buried The Gate**: `generatePlanetaryGrid()` placed the lander under the rover, so walking home through a frame destroyed the frame and teleported the lander onto it from across the map. The lander is now placed at the recorded descent site instead.
    * Sweep grew from 191 to **249 checks**. Three older checks that encoded the pre-drydock one-step install were rewritten to walk the whole salvage-carry-fit path rather than relaxed.

79. **Play-Feel Round (v1.13.0 - v1.13.1)**:
    * **Two Star Map Region Leaks**: the `YOU ARE HERE` marker was suppressed only on the *tooltip* when viewing another region's chart - the pulse and label still drew, so the ship appeared to be in a region it had left. The earlier check tested `mapTargets` and passed while the marker was plainly visible; it now samples pixels. Separately, `encounterHistory` records were **never tagged with a region at all**, so every alien ever met in the core drew on every chart. They carry `region` now and are filtered by the *viewed* region; untagged records from older saves read as core.
    * **Gate Mystery Restored**: v1.12.0 labelled singularities `GATEWAY → THE MARROW` on sight, giving the whole topology away from the first scan. A fold now reads `UNCHARTED FOLD` until the ship has been through it.
    * **Three-Zone Gravity**: a well used to be binary - nothing outside `gravityRadius`, already-doomed inside it. There is now a wide **drift zone** out to 2.4x radius that closes about 2 LY in ten seconds (enough to notice if you are watching your heading, easy to miss if you are not), then the hard well, then the horizon. Inside the well **engine authority falls and fuel burn rises** toward the core, so overdrive is a real escape only if used at once: at 80% out an immediate burn escapes and a 3-second hesitation does not; at 40% out nothing does.
    * **Autopilot**: click a point in the viewport or on the chart and the ship flies the leg. It does not skip it - 50 LY still costs 21 seconds and 21 Endurium. It hands the helm back on manual input, on a vessel coming into range, at a well boundary, or on a dry reactor, and refuses a course from an archived chart. The star map projection is now recorded and inverted exactly rather than re-derived.
    * **Long Scan Timing**: cooldown 6.0s -> 2.5s and the sweep ring clears in half a second instead of crawling across the canvas.
    * **Capped Modules Warn First (`js/ui.js`)**: a Sensor Amplifier on a Class 4 scanner installed cleanly and did nothing - the capped branch said so only *after* the module was consumed. The modal now flags it on the button and the value line, and confirms before spending it. Stacking modules (shields, hull, cargo) are flagged as repeats but not blocked, because a second one still helps.
    * **One-Use Equipment (`js/consumables.js`, `js/content/consumables.js`, NEW)**: six items, priced to be found more often than bought, held in `ship.consumables` outside the cargo hold - they take no mass, Customs has no opinion about them, and they cannot be sold to an alien port by accident. The **Precursor Fold Charge** ignores distance entirely: aim it at a charted system from the chart, or fire it blind. It is spent only when it fires, so opening the chart and thinking better of it costs nothing.
    * **Inbound Distress Calls (`js/distress.js`, `js/content/signals.js`, NEW)**: three authored beacons sat at fixed coordinates forever, and once answered the band was silent for the rest of the game. Calls now arrive during play - occasional (a floor of 150 seconds between them, at most two live), placed within reach, and they **expire**. A beacon you ignore stops transmitting and takes whatever it was carrying with it. Some carry clues; most do not, deliberately, because a beacon that always paid out would make ignoring one unthinkable. Everything ages on `ship.playClock` rather than wall clock so saves stay portable.
    * **Customs Holds Station**: cutters wandered the whole 130 LY jurisdiction, so being stopped and searched hundreds of light years from anywhere the Corps actually polices made the core feel no safer than the rim. They now loiter within 40 LY of Starbase Prime and leave for exactly one reason - a distress call inside the zone - then return. A cutter running a call does not stop to search you.
    * **Runaway Cutters (real bug, caught by probe)**: the response burn computed `run = speed * 1.8` from the cutter's *current* velocity every frame, so a dispatched cutter multiplied its own speed by 1.8 per frame - 1e306 by frame 1200 and `NaN` by frame 1208, permanently breaking patrols in any save where a call had been answered. Speed is now anchored to a `baseSpeed` captured once from the authored velocity.
    * **Harness Hygiene**: `clean()` now dismisses any modal a check provoked. A Customs stop fired during one of the new long autopilot flights and its open modal then swallowed every keyboard check that followed.
    * Sweep grew from 249 to **281 checks**.

80. **Disposition, Traffic & Motion Cues (v1.14.0)**:
    * **`aggression` Was Decoration**: `GameData.aliens` has carried an aggression value per race from the beginning - 0.3 Spemin, 0.6 Veloxi, 1.0 Uhlek - and **nothing ever read it**. Every vessel of every race fired on sight at exactly the same rate: 4 shots in 15 seconds, measured. A vessel now takes a stance when it first notices you - hostile, wary or peaceful - weighted by its race's aggression, and only a hostile one shoots. A **wary** vessel escalates to hostile while the captain is running with weapons armed, which roughly doubles how many ships will fire on you and makes arming a real decision. Firing on anything makes it hostile permanently.
    * **The Thrynn Were Never Contactable**: they had a starport, an archive and a distinct voice since v1.10.1, but no entry in `GameData.aliens` - so putting Thrynn vessels into traffic made `[C] COMMS` a control that silently did nothing. Authored in full: aggression 0.15, three dialogue moods, and a clue about the Precursor Singularity having started answering hails.
    * **Three Ships In A 500x500 Galaxy**: alien traffic was three hard-coded vessels, all in the core, so a captain could fly for an hour and meet nobody - and the deep regions were completely empty. Traffic is now generated per region from a `traffic` profile in the region data and regenerated on transit: nine vessels in the Corps Quadrant, Uhlek deep patrols in the Reach, stranded Spemin and Thrynn in the Marrow, Veloxi pickets in the Lattice. Nobody follows you through a fold.
    * **Nearby Vessels On The Chart**: live traffic was gated to `RegionManager.isCore()`, so it never appeared on any other region's chart. Now shown wherever the ship is, labelled with disposition.
    * **The Starfield Was Wallpaper**: background stars were drawn at fixed `u*w, v*h` and never moved, so with nothing else in the viewport the ship read as motionless. Stars now carry a `depth` and parallax against the ship's own position, with a speed smear on the near field at cruise.
    * **The Engines Always Burned**: the exhaust plume drew unconditionally - only its *size* responded to the boost key - so a ship coasting on momentum or sitting completely still still showed a full burn. It now draws only while thrusting (including under autopilot), with a flicker.
    * **Coordinates Were Ambiguous Across Four Regions**: `(205, 375)` is a Corps beacon in the Shattered Reach and empty sky in the Corps Quadrant. Clue coordinates and Captain's Log systems now name their chart, and every star map readout carries a `Chart:` line - added once in `updateStarMapTooltip()` rather than in each of a dozen `details` strings, so new contact types get it free.
    * **The Captain's Log Only Knew One Region**: `discoveredSystems` is region-scoped, so everything charted in the other three quadrants **vanished from the log** the moment the ship went through a fold. It now reads every region's stored record and groups systems under region headings.
    * **A Check Was Widened, Deliberately**: two checks required every clue coordinate to resolve to a *star system*. The new Thrynn clue points at the Precursor Singularity. The rule's intent is "no clue sends the captain to empty space" and a singularity is a landmark, so the rule was broadened to any charted object rather than the content being bent to fit it.
    * Sweep grew from 281 to **296 checks**.

81. **The Lattice Trap & Autopilot Consent (v1.14.1)**:
    * **An Unbreakable Loop Between Two Regions (my bug, from v1.12.0)**: the Lattice's return point was authored at `(128, 432)`, which is **11.3 LY from the Precursor Singularity** whose grip is 30 LY. That was harmless while `bh_3` was an ordinary displacement well - but v1.12.0 made it the gateway *to* the Lattice. So coming home through the Open Door dropped the ship, stationary, deep inside the mouth of the gate it had just come out of, at a depth where engine authority is far too low to climb out. Straight back to the Lattice, and around again. **The captain could not get home.**
    * **Fixed Generally, Not With A Coordinate**: `RegionManager.safeArrival()` now pushes every arrival clear of every well in the destination region, so the same trap cannot be re-authored into the next region anyone writes. Fold charges get the same clearance - an expensive way to lose a ship otherwise.
    * **Clearance Covers The DRIFT Zone, Not Just The Well**: the first attempt cleared only `gravityRadius * 1.35`, and measurement showed a ship that arrived and then idled was hauled back in after **67 seconds** with no warning it could act on. Drift is meant to be something a captain flies through and notices, not somewhere they are dropped. Arrivals now clear the full `DRIFT_SPAN`, and two minutes of complete inactivity leaves the ship where it landed.
    * **A Three-Second Transit Grace**, so a hull that arrives with zero velocity gets a breath before anything starts pulling. Counted down in frame time rather than against `ship.playClock`: the clock only advances inside `GameManager.tick()`, so keying the grace to it left gravity switched off permanently for any code path that drives the flight model directly. A transit effect should not depend on which loop is turning the crank.
    * **Autopilot Is Now SHIFT + Click, With Confirmation**: a plain click on the viewport is where the captain is *flying* - it should never silently take the helm and start burning Endurium. The prompt states destination, distance, estimated time and fuel, and warns outright when a leg would run the reactor dry before arrival. An armed fold charge still fires on a plain chart click, because arming it was already the deliberate act.
    * **Help Text Brought Current**: the in-game help still described a 6-second scan recharge (now 2.5) and Customs sweeping the full 130 LY jurisdiction (they hold station within 40 LY since v1.13.1). Added entries for SHIFT+click course-setting and for how gravity wells actually behave.
    * Sweep grew from 296 to **305 checks**.

82. **Modal Escape Routes (v1.14.2)**:
    * Reported as "the cargo log button doesn't work". **The cargo button itself could not be made to fail** - tested in hyperspace, in system, in orbit, docked and on a planet surface; with an empty hold, a full hold, and a save carrying a commodity key that no longer exists in `GameData`; after every other modal had been opened and closed; and the console was clean. The manifest opened, rendered and closed every time.
    * What the investigation *did* surface: every `.modal` is a full-screen overlay at `z-index: 100` with `pointer-events: auto`, so **any open modal makes the entire control bar unclickable** - verified with `elementFromPoint` for all thirteen. Every button on the bar reads as broken while something is open.
    * **Nine of eighteen modals had no keyboard exit**, and two of them - the icon legend and the landing-site picker - carried a button captioned `CLOSE [ESC]` while nothing was listening for Escape.     * Deliberately still un-escapable: `techpart` (Escape would silently bin a salvaged module - INSTALL and STORE both keep it), `derelict`, `distress`, `transfer` and `patrol`, each of which is an unresolved choice that Escape would quietly forfeit.
    * Sweep grew to **310 checks**, including one that asserts the guarded modals still refuse to be dismissed.

## 8. Stability & Economy Baseline (measured v1.9.20)

**20-minute automated soak** (simulated flight, combat, scanning, star map use, encounters, docking, landing; 81 samples at 15s intervals):

| Metric | Result |
| :--- | :--- |
| Frame rate | min 57.1, max 59.5, **avg 58.6 FPS** - no degradation over 20 minutes |
| JS heap | **9.5 MB flat, 0.0 MB drift** - no leak |
| Console errors | **0** (nothing swallowed by the `tick()` try/catch) |
| Bounded pools | projectiles 0-2, asteroids 7-14, ore chunks 0-1, background stars 180, log nodes capped 30 |
| `exploredSectors` | 1 -> 198, hard-capped at 400 by the 20x20 sector grid |
| `contactLog` | 0 -> 62, capped by object count (~69) |
| `encounterHistory` | 0 -> 44 and **still climbing - the only unbounded structure** |
| Save file | 1,133 -> 10,749 bytes |

`ship.encounterHistory` dedupes only within 3 LY of the same race, so it grows with exploration and is re-serialised into `localStorage` on **every** `saveGame()`. At the soak's (deliberately aggressive) encounter rate it added 44 entries in 20 minutes at roughly 90 bytes each. Not urgent - a 1,000-entry log is still only ~90 KB against a 5-10 MB quota - but it is the one structure that never stops growing. Capping it to the most recent few hundred entries would remove the last unbounded write path.

**Economy** (computed from `GameData`):

* Maxing everything - all ship tiers, all rover tiers, best crew per role - costs **$152,650**.
* A single planet surface holds a median **$78,540** in recoverable minerals, and there are **78 planets**. Two stripped worlds fund the entire game; the galaxy is roughly **40x oversupplied**.
* One-off income before mining anything: **$20,100** (6 derelicts $4,900, 3 beacons $2,300, 5 tech modules $12,900 if sold).
* Grind to fully maxed: **83 rover bed-loads** at Rover L1, ~17 at L3. One L1 bed-load of minerals averages **$1,815**.
* Fuel is not a constraint: a full 100-unit tank costs **$1,500**, less than one bed-load.
* The Starport is **sell-only** - `buyVal` is used exclusively in alien barter, so there is no buy-low/sell-high trade loop.

**Cargo capacity design (resolved in v1.9.21)**: the descending `20 -> 50 -> 45 -> 40` ladder is **intentional, not a defect**. Ablative shielding plates and cryo-containment grids are physical hardware, so they legitimately displace usable hold volume - each of the top two tiers trades 5 T of space for a capability. The Depot descriptions now state that trade explicitly instead of advertising a capacity gain. Hold *growth* comes from salvage instead (see entry 66). Still outstanding: Level 3's contraband masking has no mechanic behind it - there is no patrol or scan-detection system anywhere, and `isContraband` is declared in `data.js` and never read.

## 7. Verification & Testing Instructions

To verify game features locally:
1. Open `index.html` in any web browser.
2. Click **INITIALIZE DISPATCH JUMP** to enter Starbase Prime Spaceport.
3. Click **LAUNCH VESSEL** to enter Hyperspace.
4. Fly around in space using `W`, `A`, `S`, `D`. Approach Starbase Prime (`100, 100`) and press `[L]` to dock, or fly to Sirius Sector (`120, 85`) and press `[Enter]` to enter the solar system.
5. Orbit a planet and press `[L]` to land. On the surface, harvest minerals (`*`), press `[I]` to inspect TV cargo, drive to Lander (`[H]`), press `[U]` to unload without launching, or press `[L]` to ascend back to orbit.
6. Test Export & Import save files on the title screen.
